# KHR_character conformance fixtures

Small one-feature assets with machine-readable expected results, for any engine that implements the
KHR_character extension family. They target the normative draft at `Kjakubzak/glTF-private`
`avatar_ext_normative` `314c95c5`, whose extension payload is identical to KhronosGroup/glTF PR #2512 at
`7ab5368a`. All files are generated by `Tools/ci/generate-conformance-fixtures.py` and are CC0-1.0.

## Layout

```
conformance/
  <FIXTURE>/<FIXTURE>.gltf   self-contained glTF (buffers and images are base64 data URIs)
  <FIXTURE>/expected.json    inputs and expected outputs
  invalid/*.gltf             assets a validator must reject
  invalid/expected.json      the error expected for each invalid file
```

| Fixture | Feature | Key expected result |
|---|---|---|
| `VH-MultiRole` | roles in one hint are alternatives | `["first_person", "ACME_mirror_only"]` is drawn in the user's view, and in mirror views only when the host recognizes the ACME role |
| `VH-UnknownCustom` | unrecognized custom roles | a hint with only `ACME_unknown` imposes no restriction |
| `VH-AlwaysPlus` | `always` with other roles; `always` under a restricted ancestor | drawn everywhere; an `always` child stays hidden where its `third_person` parent is |
| `VH-Compose` | primitive AND node AND `KHR_node_visibility` | a primitive is drawn only where all three allow it; a STEP pointer animation toggles the parent's `visible` |
| `SUP-Overlap` | sum-and-clamp suppression | blends 0.4 and 0.5 give `1 * (1 - 0.9) = 0.1` (the old product rule gave 0.3); a block above its threshold gives 0 |
| `SUP-Custom` | custom type, `threshold` on a blend | the custom type contributes 0; the threshold is ignored |
| `EXPR-RotSmall` | small-rotation composition (SHOULD) | 10° about Y + 10° about X is about both; 10° + 10° about Y is about 20° |
| `EXPR-Scale` | scale composition (SHOULD), `t = e*T`, neutral sample `n` | 1→2 and 1→3 give 4 (multiplying gives 6); translation uses `n`, not `b` |
| `TT-Atlas` | texture-transform offset, rotation, scale | STEP atlas cells add; 7 rad stays 7 rad; scale 0.5 + 0.5 + 0.25 = 1.25 |
| `CAM-Default` | `default_view` selection, custom roles, subject point | node 2 of the default views on nodes 2, 5 and 9; `ACME_inspect` is not surfaced |
| `LOOK-Animated` | look-at target point | the global translation under an animated, rotated and scaled parent, per instance |
| `REF-Poses` | reference poses | targeted TRS from the single key, everything else authored (including `matrix`) |

## expected.json

Every file has:

- `fixture`, `asset` (the `.gltf` file name), `license`, `spec` (the targeted draft), `summary`, and optionally
  `notes`;
- `kind`, one of `visibility`, `suppression`, `expression`, `camera_hint`, `lookat_target` and
  `reference_pose`;
- `cases`. Each case has a `name`, a `level` (`MUST` for a requirement, `SHOULD` for a recommendation), the
  `spec_section` it checks, an `input`, and the `expected` output.

Nodes are named, and names are unique within a fixture, so the fixtures don't depend on how an engine
numbers its objects. Properties are identified by `KHR_animation_pointer`-style JSON pointers such as
`/nodes/1/translation`. A number is correct within `tolerance` when one is given, and within 1e-6
otherwise. Booleans compare exactly.

### `visibility`

- `input.host.logic`: the roles the application has logic for. A standard role that is not listed applies in
  every view. A custom role that is not listed is unrecognized and ignored.
- `input.host.applies`: the roles from `logic` that apply in the evaluated render view.
- `input.state` (optional): `{"animation": name, "time": t}` is the evaluation state reached by sampling that
  animation at `t`. `{"animation": null}` means the authored values.
- `expected.nodes`: whether each named node's own content is drawn (`renderNodeVisualContent`).
  `expected.primitives`: whether primitive `i` of a named node is drawn (`"Name#i"`,
  `renderPrimitiveInstance`).

A hint allows a view when its roles include `always`, when it has no recognized role, or when at least one
recognized role applies. Ancestor hints, the primitive hint and `KHR_node_visibility` are ANDed.

### `suppression`

- `input.drivers`: native driver values by expression name. A missing name is 0, and values are clamped to
  [0, 1].
- `expected.effective`: the effective drivers `v` by name, after suppression.

### `expression`

- `input.drivers`: as for `suppression`. Suppression applies first when the fixture has any.
- `expected.properties`: a list of entries, each in one of three forms.
  - `{"target", "value", "tolerance"}`: the composed expression value for that property.
  - `{"target", "value": null}`: the expressions produce no response for that property. An effective driver
    of 0 returns an empty response.
  - `{"target", "rotation_vector_deg", "tolerance_deg"}`: the composed node rotation, as an axis-angle vector
    in degrees (unit axis times angle). Each component must be within `tolerance_deg`.

Additive properties are node translation, morph weights, and texture-transform offset and rotation. They
are composed as `y = b + sum(s - n)` (MUST). Here `b` is the authored initial value, `s` the sample at
`t = e*T`, and `n` the same channel's sample at `t = 0`. Node scale and texture-transform scale use the
same formula as a SHOULD. Node rotation is host-defined, and SHOULD be approximately additive for small
angles. The SHOULD tolerances accept an axis-angle sum and quaternion multiplication in either order.

### `camera_hint`

- `input.query: "default_view"`, with `input.host.recognized_custom_roles`. `expected.node` and
  `expected.node_index` give the hint a host chooses as its default view.
- `input.query: "default_affordances"`. `expected.nodes` gives the hints a host may surface in default
  camera affordances, in node order. Hints with unrecognized custom roles are left out.
- `input.query: "pose"`. For each hint node, `expected.hints` gives the initial camera `position` (global
  translation), the `forward` direction (local −Z in global space) and the `subject_point` (the
  `targetNode`'s global translation, or null).

### `lookat_target`

- `input.instances`: one evaluation `state` per asset instance.
- `expected.instances`: for each instance, the target point of every marker, in the asset's coordinate
  space.

### `reference_pose`

- `input.animation`: the name of a tagged animation. `expected` gives its `poseType`, the resolved `local`
  value of each listed node (TRS, or the authored `matrix`) and selected `global_translation`s.
- `input.query: "tagged_animations"`. `expected.animations` gives the names of the tagged animations.

## invalid/expected.json

`files` maps each invalid file to the following:

- `error_codes`: the codes `Tools/ci/validate-character-json.py` must report. It must report at least one,
  and no codes outside the list.
- `reason`: the rule the file breaks.
- `spec_section`: where the spec states that rule.

Other validators can match on `reason`. Each file breaks one rule:

- a visibility hint or camera hint listed in `extensionsRequired`;
- `role` without `roles`;
- a camera hint whose `targetNode` is its own node;
- a duplicate expression name;
- a mapping weight of 1.5;
- a joint channel on a node with `matrix`;
- one channel listed by two derived extensions.

## Checks

```sh
python3 Tools/ci/generate-conformance-fixtures.py --check      # committed files match the generator
python3 Tools/ci/conformance_reference.py                      # an independent evaluator agrees with expected.json
python3 Tools/ci/validate-character-json.py --spec <glTF checkout> Tools/fixtures/conformance/[A-Z]*/*.gltf
python3 Tools/ci/validate-character-json.py --spec <glTF checkout> \
  --expect-invalid Tools/fixtures/conformance/invalid/expected.json
```

The `<glTF checkout>` is KhronosGroup/glTF at `7ab5368a87d1d303dff33ec5f9aad42752e84c78`, or glTF-private
at `314c95c5`; it must contain `specification/2.0/schema` and `extensions/2.0/Khronos`. CI runs all four
checks in the `Character fixture checks` job.
